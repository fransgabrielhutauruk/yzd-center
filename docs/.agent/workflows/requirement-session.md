# Workflow: Sesi Requirement

Alur kerja untuk sesi diskusi requirement baru.

## Sebelum Sesi
- [ ] Baca SRS.md versi terbaru untuk memahami konteks yang ada
- [ ] Baca catatan/ untuk melihat keputusan yang sudah dibuat
- [ ] Siapkan pertanyaan klarifikasi jika ada requirement yang ambigu

## Selama Sesi Diskusi

### Yang BOLEH:
- Jawab pertanyaan langsung di chat
- Usulkan opsi/alternatif dengan trade-off
- Tanya kembali jika requirement tidak jelas (Socratic Gate)
- Buat draft outline sebelum dokumen lengkap

### Yang DILARANG:
- Langsung tulis dokumen lengkap tanpa konfirmasi outline dulu
- Menebak requirement yang ambigu dan mendokumentasikannya sebagai fakta
- Mengubah SRS.md tanpa konfirmasi eksplisit dari user
- Menambahkan asumsi teknis sebagai keputusan final

## Alur Pencatatan

Jika ada saran/rekomendasi substansial:
1. Sampaikan saran + alasan + alternatif singkat di chat
2. Tanya: Apakah saran ini perlu dicatat ke catatan/?
3. Jika ya: simpan ke catatan/YYYY-MM-DD_topik.md
4. Beri tahu path file yang disimpan

## Alur Update SRS

Jika ada perubahan requirement:
1. Identifikasi bagian SRS yang perlu diubah
2. Tunjukkan perubahan yang akan dilakukan
3. Minta konfirmasi user sebelum menyimpan
4. Update SRS.md dengan changelog versi baru
5. Periksa konsistensi dengan catatan/ yang sudah ada

## Setelah Sesi
- [ ] Pastikan semua keputusan penting sudah tercatat (di catatan/ atau SRS.md)
- [ ] Update status di catatan/ yang relevan jika ada keputusan baru
- [ ] Tandai item yang masih perlu diskusi lebih lanjut
